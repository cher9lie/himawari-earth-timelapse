# 处理方法

1. 日期按指定固定 UTC 时差解释，开始包含、结束不包含。全范围使用连续时间栅格，不在午夜重新开始采样，因此 50 分钟等非整除一天的间隔也不会产生重复时间。
2. 每个观测并行读取 NICT 可见光 `D531106/2d/550` 四块及 `FULL_24h/B13/2d/550` 四块，合成 1100×1100 圆盘。RGB 和 B13 的 URL 时间相同。
3. B13 在此接口是带透明度的展示云图，以 alpha 作云层强度，**不是亮温数据**。使用地球静止卫星导航几何和 NOAA fractional-year 近似太阳位置计算夜侧；日落到太阳高度 -8° 平滑过渡到深蓝背景 / 浅色红外云。白昼与圆盘外像素保持可见光源色。
4. 404、No Image 占位、缺少 B13 alpha、无法解码的 PNG 视为缺测。瞬态 HTTP/PNG 错误最多重试四次；网络错误重试耗尽明确失败，不把所有网络异常当成观测缺失。
5. 替代只允许一整套同步 RGB/B13 影像对，离标称时间不超过20分钟，图上打印实际观测时间。缺测 JSONL 保留标称时间、实际时间、偏移和原因；断点恢复时当天重跑可能产生重复审计行，按标称/实际时间去重可用于统计，日志不删除历史尝试。
6. 每帧经 Pillow 重采样与文字标注，直接写 FFmpeg RGB 管道，H.264 / CRF / yuv420p 编码。POSIX 下对管道设置30秒写入截止；Windows 本地管道依赖 FFmpeg 进程，卡住时在终端中止并恢复当天。
7. 每日分段经 ffprobe 检查帧数、尺寸、FPS、时长后发布至持久化目录，记录配置键和 SHA256。恢复先验证分段散列，成功才跳过。最后将分段复制到临时盘，用 stream copy 拼接并 faststart，再校验全片。
8. 最终 MP4 的全文件 SHA256、字节数和视频元数据保存在 manifest；电脑通过8MiB分块取回，每块核对SHA256，已下载前缀重新核对，全片散列吻合才把 `.part` 改名为 MP4。仅成功后释放专用运行时。

导航参数参考 NICT 网站 tile viewer。太阳近似参考 [NOAA Solar Calculation Details](https://gml.noaa.gov/grad/solcalc/calcdetails.html)。画面是展示合成，不用于定量科学反演；不宣称真实可见光夜景。
